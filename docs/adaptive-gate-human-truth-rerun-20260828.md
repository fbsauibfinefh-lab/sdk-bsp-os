# 461 参数自适应字段门控人工真值复跑

本文记录 2026-08-28 使用三套平行真值重新训练和评测自适应字段门控器的完整协议。结论仅针对 461 参数门控消融，不改变 BSPForge 的最终层级约束与 q4 API 家族解码方法。

## 1. 复跑目的

旧实验使用自动分级弱监督真值训练。门控器在开发集表现很好，但三块外部板卡 SDK 上仅达到 P@1 0.680、Recall@5 0.699、MAP 0.662 和 nDCG@10 0.697。新获得 H01、H02 两套人工源码审计真值后，本轮回答两个问题：

1. 人工真值能否改善门控器的跨 SDK 外部效果；
2. 改善是否足以让门控器进入论文最终方法。

## 2. 三套平行真值

| 真值 | 来源 | 原始查询组 | 0/1/2/3 级条目 |
| --- | --- | ---: | --- |
| `automatic-v0.9` | 可审计自动分级弱监督 | 418 | 25165/489/570/777 |
| `human-engineer-1` | 工程师 H01 源码审计 | 418 | 0/39/106/265 |
| `human-engineer-2` | 工程师 H02 源码审计 | 418 | 164/240/163/397 |

三套板卡 SDK 不属于训练真值。H01、H02 不合并、不投票、不仲裁，分别产生独立模型。由于两人尚未对候选并集补齐缺失评分，本轮不计算 Kappa，也不把任一单人版本称为最终金标准。

## 3. 真值与函数候选对齐

排序器当前以 Migration IR 中的函数实体为候选。全量审计结果如下：

| 真值 | 正相关符号 | 不可达符号 | 原因 |
| --- | ---: | ---: | --- |
| 自动真值 | 1,836 | 0 | 全部可映射函数实体 |
| H01 | 381 | 10 | CMSIS/兼容层宏、C++ 限定名、兼容 API 名称 |
| H02 | 617 | 0 | 全部可映射函数实体 |

H01 的典型例子是公共宏 `NVIC_SetPriority` 映射到内部函数 `__NVIC_SetPriority`，以及 `HardwareSerial::begin` 在 IR 中表现为未限定方法名。直接把宏名改写为函数名会改变人工标注语义并可能引入歧义，因此本轮没有自动猜测别名。

数据生成器新增两种显式策略：

- `error`：默认策略，遇到不可达真值立即失败；
- `skip-missing`：记录不可达符号；若同组还有可达正例则继续，若没有则跳过该查询组。

H01 本轮显式使用 `skip-missing`。所有 10 个符号都保存在数据集 `truth_alignment`，没有静默删除。

## 4. 公平候选采样修复

首次复跑发现旧生成器使用一个全局随机流抽取易负例。人工真值会跳过更多 `no_public_api` 查询组，从而改变后续随机状态，导致三套真值连外部板卡负例都不完全相同。

修复后，每个查询组使用字符串种子：

```text
seed : sdk_id : capability.operation
```

负例抽样和候选洗牌只受本组标识影响。三套公平数据集的 50 个外部查询组已经逐实体比较，候选集合与顺序完全一致。该修复是得到可信真值对比的必要条件。

## 5. 特征缓存与无泄漏说明

冻结 MiniLM 的五字段 MaxSim 分数仅由操作契约和候选 `candidate_text` 决定，与标签无关。本轮新增可审计缓存脚本：

- 缓存键：`operation_id + candidate_text`；
- 缓存值：五个字段 MaxSim 与总字段迟交互分数；
- 缓存未命中：使用固定修订的 `all-MiniLM-L6-v2` 在 CPU 上补算；
- 标签、真值 ID 和候选等级不参与缓存键或模型输入。

因此复用字段分数不会把 H01/H02 标签泄漏到候选表示。

## 6. 训练与评测协议

- 模型参数：461；
- 基础编码器：冻结 `all-MiniLM-L6-v2`；
- 损失：四级 listwise 交叉熵 + pairwise softplus；
- 负例：课程式难负例；
- 最大轮次：80；
- 训练随机种子：20260826；
- 训练/开发划分：按独立 SDK 组，开发组固定为 Raspberry Pi、Espressif、Renesas、libopencm3；
- 外部评测：K210、STM32F103、PSoC E84，共 50 个查询组；
- 统计：10,000 次查询级配对 bootstrap。

本轮是单训练随机种子的探索性复跑。bootstrap 衡量外部查询抽样不确定性，不代替多随机种子训练方差。

## 7. 数据规模与开发结果

| 真值 | 训练 SDK | 训练组 | 开发组 | 开发 P@1 | 开发 R@5 | 开发 MAP |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 自动真值 | 22 | 314 | 86 | 0.779 | 0.631 | 0.710 |
| H01 | 20 | 205 | 73 | 0.247 | 0.475 | 0.348 |
| H02 | 20 | 206 | 75 | 0.293 | 0.445 | 0.398 |

人工真值开发指标明显偏低。可能原因包括：人工真值更强调公共 API 层和真实可调用方向，而当前门控器只能在已有 19 个连续特征上做小幅有界调权；两位工程师对 `no_public_api` 和相关实现的覆盖也不同，导致有效训练组减少约三分之一。

## 8. 外部板卡结果

| 训练真值 | P@1 | Recall@5 | MAP | nDCG@10 |
| --- | ---: | ---: | ---: | ---: |
| 自动真值公平基线 | 0.680 | 0.719 | 0.680 | 0.716 |
| H01 | **0.720** | **0.772** | **0.715** | **0.765** |
| H02 | **0.720** | **0.772** | 0.713 | 0.755 |

旧历史结果为 0.680/0.699/0.662/0.697，但其外部负例由全局随机流产生，不能与公平复跑做严格配对比较。

人工真值相对公平自动基线的增量如下：

| 对比 | ΔP@1 | ΔRecall@5 | ΔMAP | ΔnDCG@10 |
| --- | ---: | ---: | ---: | ---: |
| H01 - 自动 | +0.040 | +0.053 | +0.035 | +0.049 |
| H02 - 自动 | +0.040 | +0.053 | +0.033 | +0.038 |

H01 的 95% 区间分别为 `[-0.060,0.140]`、`[-0.013,0.123]`、`[-0.023,0.090]`、`[-0.006,0.103]`；H02 分别为 `[-0.060,0.140]`、`[-0.017,0.123]`、`[-0.025,0.087]`、`[-0.016,0.094]`。所有区间均跨 0，不能作统计显著声明。

## 9. 选择性接受与最终方法

自动真值模型可在开发集校准出阈值，外部接受 17/50，经验精度 1.00。H01/H02 在各自开发集上都找不到满足目标精度 0.95 且至少接受 5 组的阈值。这说明人工真值模型虽然平均排序改善，置信度排序尚不稳定。

最终 q4 方法不读取自适应门控分数，三套公平数据上的结果完全一致：

| 方法 | P@1 | Recall@5 | MAP | nDCG@10 |
| --- | ---: | ---: | ---: | ---: |
| 确定性 q4 最终方法 | 0.800 | 0.926 | 0.803 | 0.864 |

## 10. 结论

人工真值对 461 参数门控产生了方向一致的外部改善，说明旧自动真值确有一部分规则偏差；但改善尚不显著，开发集性能低，选择性接受失败，且四项指标仍低于最终方法目标。因此当前定位不变：

- 461 参数门控继续作为负向消融；
- 不进入论文最终方法，也不作为主要性能来源；
- 论文可以报告“人工真值带来一致改善但不足以解决跨 SDK 泛化”；
- 最终主张仍由冻结字段迟交互、层级/操作契约和 q4 API 家族覆盖解码支撑。

## 11. 后续工作

1. 对 H01/H02 候选并集补齐 0/1/2/3 级评分并仲裁冲突；
2. 将宏、C++ 方法和函数实体的别名关系正式建模进 Migration IR，而不是在真值层猜测改名；
3. 对三套真值至少运行 5 个训练随机种子，报告均值、标准差和配对效应；
4. 在不参与调参的新 SDK 上执行一次性确认测试；
5. 若门控仍无稳定提升，停止扩展该分支，保持确定性 q4 为最终方法。
