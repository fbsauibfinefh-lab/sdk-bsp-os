# 研究原型状态与版本演进

本文件按版本保留研究原型的演进记录。每个版本只描述当时新增或达到的能力，不用最新版覆盖旧版历史。

## v0.1：端到端骨架

- 建立 SDK Ingestor、IR Store、Semantic Resolver、Closure Solver、Build Diagnoser 和 OS Backend 六个模块。
- 支持 K210 SDK 的 C/C++/汇编、构建规则、链接脚本和启动资产摄取。
- 建立版本化 SDK Migration IR、稳定实体 ID 和源码证据位置。
- 生成隔离的 RT-Thread K210 BSP，调用 RISC-V 工具链并产出首个 ELF/BIN 基线。

该版本验证了“SDK 输入到可编译 RTOS 工程”的主流程可行，但功能绑定仍以元数据和工程拼装为主。

## v0.2：功能绑定与编译反馈闭环

- 生成时钟、中断、UART、GPIO 和定时器的可调用 SDK 适配函数。
- 将每项绑定关联到 SDK 符号、签名、实体 ID、源码路径和行号。
- 将绑定依赖的 SDK 源文件自动加入 SCons 构建规则。
- 识别缺失头文件、未定义符号、重复定义、ABI 不匹配、内存区溢出、缺失库和一般编译错误。
- 对缺失头文件和未定义符号执行有证据的增量闭包修复，并进行有界重新生成和编译。
- 保存每轮日志、诊断、修复提案、闭包版本和停止原因。

该版本已形成“可调用 SDK 适配层”，但尚未生成 RT-Thread 原生设备操作表、设备实例和注册代码。

## v0.3：RT-Thread 原生设备模型与论文实验基础

### 原生设备生成

- 生成 `bspforge_uart_ops`，实现 configure、control、putc 和 getc，并通过 `rt_hw_serial_register` 注册 UART 设备。
- 生成 `bspforge_pin_ops`，实现模式、读写、中断挂接、解绑和使能，并通过 `rt_device_pin_register` 注册 PIN 设备。
- 生成 `bspforge_hwtimer_ops`，实现初始化、启动、停止、计数读取和控制，并通过 `rt_device_hwtimer_register` 注册硬件定时器。
- 设备名称、UART 通道、波特率、PIN 数量、TIMER 设备/通道和计数频率均由项目 JSON 配置。
- 生成独立设备名，保留原 K210 BSP 驱动，便于后续上板时进行并行对照。

### 绑定语义与构建闭环

- UART 数据位、停止位和校验位经过显式归一化，不直接假设 SDK 与 RT-Thread 枚举数值相同。
- GPIO 输入、上下拉、输出和中断边沿经过显式映射。
- 硬件定时器使用 K210 TIMER 外设，不复用 RT-Thread 系统节拍所占用的 CLINT。
- 自动启用生成设备需要的 RT-Thread 功能宏，并生成缺失的 K210 `drv_hw_timer.c` 后端文件。
- 真实 K210 构建在第 1 轮定位 4 个未定义系统调用符号，第 2 轮加入一个提供者源文件后成功链接。

### 产物与实验验证

- 编译成功必须同时满足：SCons 返回码为 0、ELF/BIN 非空、ELF 目标为 RISC-V、段信息可读、预期操作表与注册函数均进入 ELF。
- 记录 ELF/BIN 大小和 SHA-256、text/data/bss、每轮构建耗时、重生成耗时与警告分类。
- 提供 K210 人工真值集，自动计算语义映射 Precision/Recall/F1、Recall@K、MRR、绑定符号覆盖率和设备操作覆盖率。
- 自动运行名称、路径、签名、头文件、调用、宏等七类证据消融，不需要修改解析器代码。
- 当前 11 项单元测试与 GitHub CI 覆盖模块逻辑、诊断类别、设备生成、配置拒绝、评估和产物解析。

## 后续主体工作

以下三项仍需作为扩大论文证据范围的独立工作开展：

1. 增加具有不同设备模型和构建系统的第二个 RTOS 后端。
2. 增加更多芯片 SDK，形成跨厂商、跨架构样本。
3. 在 K210 开发板上执行启动、UART、GPIO、中断和定时器回归。

除上述三项外，当前代码结构、数据格式、自动化流水线和评估接口已经形成论文实验基础。后续实验可以继续增加样本、重复次数和统计分析，不需要重写主流程。

## 结论边界

当前结果证明生成代码能够进入 RT-Thread 原生设备模型，并在真实 K210 SDK、RT-Thread 和 RISC-V 工具链上形成可验证固件。它尚不证明固件已经在开发板启动，也不证明外设运行语义完全正确；这些结论必须由后续上板实验单独给出。
