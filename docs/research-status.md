# 研究原型状态与版本演进

本文件按版本保留研究原型的演进记录。每个版本只描述当时新增或达到的能力，不用最新版覆盖旧版历史。

## v0.1：端到端骨架

- 建立 SDK Ingestor、IR Store、Semantic Resolver、Closure Solver、Build Diagnoser 和 OS Backend 六个模块。
- 支持 K210 SDK 的 C/C++/汇编、构建规则、链接脚本和启动资产摄取。
- 建立版本化 SDK Migration IR、稳定实体 ID 和源码证据位置。
- 生成隔离的 RT-Thread K210 BSP，调用 RISC-V 工具链并产出首个 ELF/BIN 基线。

该版本验证了“SDK 输入到可编译 RTOS 工程”的主流程可行，但功能绑定仍以元数据和工程拼装为主。

## v0.2：功能绑定与编译反馈闭环

- 生成时钟、中断、UART、GPIO 和定时器的可调用 SDK 适配函数。
- 将每项绑定关联到 SDK 符号、签名、实体 ID、源码路径和行号。
- 将绑定依赖的 SDK 源文件自动加入 SCons 构建规则。
- 识别缺失头文件、未定义符号、重复定义、ABI 不匹配、内存区溢出、缺失库和一般编译错误。
- 对缺失头文件和未定义符号执行有证据的增量闭包修复，并进行有界重新生成和编译。
- 保存每轮日志、诊断、修复提案、闭包版本和停止原因。

该版本已形成“可调用 SDK 适配层”，但尚未生成 RT-Thread 原生设备操作表、设备实例和注册代码。

## v0.3：RT-Thread 原生设备模型与论文实验基础

### 原生设备生成

- 生成 `bspforge_uart_ops`，实现 configure、control、putc 和 getc，并通过 `rt_hw_serial_register` 注册 UART 设备。
- 生成 `bspforge_pin_ops`，实现模式、读写、中断挂接、解绑和使能，并通过 `rt_device_pin_register` 注册 PIN 设备。
- 生成 `bspforge_hwtimer_ops`，实现初始化、启动、停止、计数读取和控制，并通过 `rt_device_hwtimer_register` 注册硬件定时器。
- 设备名称、UART 通道、波特率、PIN 数量、TIMER 设备/通道和计数频率均由项目 JSON 配置。
- 生成独立设备名，保留原 K210 BSP 驱动，便于后续上板时进行并行对照。

### 绑定语义与构建闭环

- UART 数据位、停止位和校验位经过显式归一化，不直接假设 SDK 与 RT-Thread 枚举数值相同。
- GPIO 输入、上下拉、输出和中断边沿经过显式映射。
- 硬件定时器使用 K210 TIMER 外设，不复用 RT-Thread 系统节拍所占用的 CLINT。
- 自动启用生成设备需要的 RT-Thread 功能宏，并生成缺失的 K210 `drv_hw_timer.c` 后端文件。
- 真实 K210 构建在第 1 轮定位 4 个未定义系统调用符号，第 2 轮加入一个提供者源文件后成功链接。

### 产物与实验验证

- 编译成功必须同时满足：SCons 返回码为 0、ELF/BIN 非空、ELF 目标为 RISC-V、段信息可读、预期操作表与注册函数均进入 ELF。
- 记录 ELF/BIN 大小和 SHA-256、text/data/bss、每轮构建耗时、重生成耗时与警告分类。
- 提供 K210 人工真值集，自动计算语义映射 Precision/Recall/F1、Recall@K、MRR、绑定符号覆盖率和设备操作覆盖率。
- 自动运行名称、路径、签名、头文件、调用、宏等七类证据消融，不需要修改解析器代码。
- 当前 11 项单元测试与 GitHub CI 覆盖模块逻辑、诊断类别、设备生成、配置拒绝、评估和产物解析。

## v0.4：三芯片、双 RTOS 迁移矩阵

### 输入与后端扩展

- 增加官方 STM32CubeF1 SDK 和 PSoC E84 Edgi-Talk SDK，形成 Kendryte、ST、Infineon 三个厂商样本。
- 增加 Zephyr 4.4 后端，生成原生 devicetree/Kconfig/CMake 应用并调用 `west build`。
- K210 增加仓库内可复现的 Zephyr 板级端口，覆盖 SRAM、PLIC、机器定时器、UARTHS、启动入口和 FPIOA 串口初始化。
- STM32F103 与 PSoC E84 复用 RTOS 已有 HAL/PDL 和设备驱动，通过 `native-driver-trace` 分别记录 RTOS 驱动调用和原生 HAL provider 证据，避免把函数定义误计为调用。
- Zephyr 构建成功后从 `build.ninja` 提取本次实际编译的驱动源文件，再刷新直接调用证据；未参与当前板级构建的驱动不计入直接绑定。
- RT-Thread 原生路径生成 UART、PIN 和软件定时器验证入口；Zephyr 原生路径生成 console、GPIO 与 `k_timer` 验证入口，关键函数均进入最终 ELF。

### 构建与验证结果

- K210、STM32F103、PSoC E84 在 RT-Thread 与 Zephyr 上的六个组合均完成编译和链接，矩阵成功率为 6/6。
- 所有组合均验证 ELF 非空、目标架构正确、段信息可读、关键验证/注册符号已链接；可刷写的 BIN 或 HEX 也经过大小和 SHA-256 记录。
- PSoC E84/Zephyr 的上游后处理要求对 ELF 原地调整 LMA。后端使用受控 `objcopy` 包装器保留原始 ELF，并在生成 HEX 时应用相同偏移，避免修改 Zephyr 源码。
- `scripts/run_matrix.sh` 可依次复现六项实验；`docs/matrix-results.md` 保存本轮输入版本、规模与固件统计。
- 单元测试由 11 项增加到 15 项，新增原生驱动证据追踪、RT-Thread 验证源码、Zephyr 工程契约和实际编译源文件筛选测试。

该版本完成了原计划中的第二 RTOS 和更多芯片 SDK。现有结果是“生成、编译、链接和静态产物验证”闭环；三块实物开发板的启动与外设回归仍作为独立实验阶段。

## v0.5：混合语法前端、通用绑定契约与实板实验工具

### SDK 恢复与语义实验

- SDK Ingestor 增加 `hybrid` 与 `regex` 两种可切换模式。混合模式按 Clang AST、tree-sitter、正则兜底的顺序解析，并为每个文件记录实际前端、失败原因和实体置信度。
- 文件级语法解析采用最多 8 个工作线程；STM32CubeF1 的混合解析从串行试验的约 260 秒降至约 39 秒。
- 保留固定权重排序器作为基线，新增 LightGBM LambdaRank 模型加载、训练脚本和固定权重/学习排序对照脚本。训练数据必须按 SDK 分组，正式结果采用 leave-one-SDK-out。
- 新增规范化能力模式和 `canonical-binding-plan.json`。19 个常见操作分别记录自动选择的 SDK 符号、签名、参数来源、替代项、置信度和缺失状态，两个 OS 后端都消费该计划。
- 当前自动计划在 K210、STM32CubeF1、PSoC E84 上分别推断 19/19、11/19、14/19 个操作。该结果是未由人工 profile 填平的真实自动化覆盖，后两者仍需真值和排序改进。

### 闭包与诊断

- 启动和链接资产不再无条件全部加入。R6 根据构建引用、架构、芯片、CPU 核、工具链、入口符号及后端替换策略给出逐项选择/拒绝证据。
- STM32F103 和 PSoC E84 的 RTOS 工程明确使用 `backend` 资产策略，由既有 BSP/Zephyr 后端提供启动与链接契约；K210 继续选择 SDK 中唯一匹配资产。
- 诊断修复增加 low/medium/high 风险，缺失头文件和唯一符号提供者为低风险，唯一静态库为中风险，ABI、内存区和重复定义保持人工处理。
- 每次修复记录基闭包、候选闭包和诊断代价；若下一轮诊断恶化，流水线从基闭包重新生成工程并以 `repair-regression-rolled-back` 停止。

### 跨 RTOS 上板协议

- RT-Thread 与 Zephyr 固件均加入版本为 1.0 的统一自测入口和逐行 JSON 结果。
- 主机端 `bspforge-hwtest` 支持启动等待、重复轮次、命令请求 ID、超时、原始日志和 JSON 汇总。
- 报告包含启动成功数/总数、成功率、启动时间均值/范围、命令通过数/适用总数、失败数和 unsupported 数。
- 当前六组固件均重新编译通过，自测入口或分发循环已进入最终 ELF；真实启动时间和外设结果尚未产生，必须由三块开发板烧录后填写。

### 评估口径修正

- 一个能力可接受多个互补操作，不再按“一个能力一个函数”解释。
- 空真值或 SDK 不支持的能力标为 not-applicable，不再错误计为 1.0；宏平均忽略不适用项，并单列错误支持声明。
- 人工 profile 仅作为 oracle 和已知平台专用实现，不计为自动绑定结果；自动链路分别报告候选覆盖、操作绑定和 RTOS 设备操作覆盖。
- 单元测试由 15 项增加到 21 项，覆盖两种前端、通用绑定计划、目标资产筛选、风险策略、N/A 指标和硬件协议汇总。

## v0.6：跨 SDK 真值、学习融合与可执行仿真

### 语义语料与真值

- 新增 Pico SDK 2.2.0、nrfx 4.2.1、ESP-IDF 6.0.1 和 MCUXpresso SDK 2.16.100 四个官方语义样本，与现有三套 SDK 组成 7 SDK 语料。
- 混合前端开始解析头文件中的 `static inline` 实体；7 套 IR 共包含 35,837 个文件和 198,594 个函数。NXP 深层语法树触发的递归上限问题已改为显式栈遍历并加入回归测试。
- 建立 7 份源码审计真值、清单、逐符号定义核验和可检索性检查。nrfx 的通用 IRQ 控制由平台宏提供，明确标为函数排序不适用。
- 自动构建 34 个 SDK-能力组、4,340 个候选和 260 个正例实体；训练保留有限重复实现，测试按唯一 API 符号去重。

### 学习与统计实验

- 学习特征由 8 项扩展到 19 项，增加基线分数、能力/动作共现、公共驱动路径、测试路径、内部符号和标识符形态等可解释特征。
- 增加只消费函数名和源码路径的标准 BM25 词法基线，避免实验仅比较系统内部版本。
- 实现外层 leave-one-SDK-out、内层 SDK 留一融合权重选择、逐特征消融、10,000 次 Bootstrap 区间和 20,000 次配对置换检验。
- 纯学习总体弱于固定权重；嵌套融合在 Recall@5、Recall@10、MAP 和 nDCG@10 上呈正向趋势，但当前置信区间跨越 0，文档不作显著优越性声明。
- 训练全部语料得到可直接加载的 `models/semantic-ranker.txt`，Resolver 新增 `hybrid` 模式并从模型元数据读取推荐融合权重。

### 仿真回归

- 主机验证工具新增进程传输层，同一协议可连接串口、native executable、QEMU 或 Renode。
- 新增 Zephyr `native_sim/native/64` 工程配置、host toolchain 支持和 stdin/stdout UART 自动化配置。
- native_sim 完整构建和 ELF 验证通过；20/20 次启动成功，100/100 条适用命令通过，40 条需要真实连线的命令保持 unsupported，未计为通过。
- 新增实验规模与仿真方案文档，明确三块实板是硬件验证下限，仿真用于重复性和故障注入而非替代真实外设。
- 使用扩展后的头文件 API 实体重跑 3 SDK × 2 RTOS 全矩阵，六组工程均通过编译、架构、段信息和关键符号检查；当前自动操作绑定为 K210 19/19、STM32F103 15/19、PSoC E84 13/19。
- 单元测试增加到 26 项，覆盖深层语法树、头文件内联 API、真值审计、BM25 基线、学习特征契约和模拟器进程传输。

该版本使除真实硬件采集和第二人真值复核之外的主要实验流水线进入可复现状态。

## v0.7：20 个独立 SDK、操作级排序与置信拒答

### 语料与隔离协议

- 开发语料由 7 套扩展到 22 套 SDK，按共同厂商或上游合并为 20 个独立性分组。
- K210、STM32F103、PSoC E84 三套拟上板 SDK 改为严格外部测试角色，不参与弱标签生成、模型训练或参数选择。
- 新增 19 个规范化操作的源码审计真值；不适用的宏接口、回调覆写和缺失功能不计入测试分母。
- 操作级数据包含 391 个训练查询组、37,808 个候选和 3,012 个弱正例；外部测试包含 50 个适用操作组。

### 操作排序与可靠性

- Resolver 新增 `operation-weighted`，分别排序 UART 读写、GPIO 配置/读写/中断、定时器初始化/启停/周期等操作。
- 增加 HAL 抽象层、中断控制器、参数化开关、反义操作、私有/测试 API、适配方向和操作冲突等证据。
- 识别 `set_enable(..., bool)` 一类双向操作，避免 stop/disable 被名称反义规则错误淘汰。
- 识别端口层中反向调用 RTOS API 的包装函数，避免把 OS 到 SDK 的适配方向颠倒。
- Resolver 增加 `operation_min_margin`；第一名与第二名分差不足时输出 `abstained`，不再强制生成低置信绑定。

### 当前实验结果

- 在三套完全外部板卡 SDK 的 50 个操作组上，BM25 的 P@1/MAP 为 0.220/0.346，操作级静态方法为 0.540/0.554。
- 纯弱监督 LambdaRank 的 P@1/MAP 仅为 0.200/0.327，说明当前瓶颈是标签质量和跨 SDK 泛化，而不是候选行数不足。
- 轻量语义嵌入与静态证据等权融合的 P@1/MAP 为 0.600/0.628；MAP 增量的 bootstrap 95% 区间为 `[0.012, 0.146]`。融合权重仍需在独立开发集上预先确定。
- 静态方法在置信分差 0.05 时覆盖 24% 的操作，选择性精度为 91.7%；该机制已可用于高置信自动接受和低置信人工审查。
- 新增 CodeRankEmbed 固定版本入口、外部角色选择和嵌入消融脚本；本机完整代码模型训练嵌入受 CPU 性能限制，未作为已完成结果报告。

该版本把“编译通过”和“操作语义正确”明确拆开。编译矩阵仍是构建闭包证据，外部操作排序与实板回归分别提供语义和运行证据。

## v0.8：冻结小模型、IR 查询适配与三路语义融合

### 模型筛选与输入契约

- 对比 all-MiniLM-L6-v2、BGE-small-en-v1.5、Granite embedding small English R2 和 MiniLM cross-encoder，并固定每个模型的上游提交。
- 最终选择 22.7M 参数、88 MiB 的 all-MiniLM-L6-v2。BGE 融合 MAP 为 0.605，未超过 MiniLM；Granite 在当前 CPU 上约 19 秒/批，不满足运行成本目标。
- 操作查询直接由 Migration IR 的 capability、operation 和 contract 序列化；候选由文件、符号、签名、包含和调用关系序列化，最大长度固定为 128 token。

### 内部调优与负向结果

- 最后两层三元组调优在开发集上把 MAP 从 0.336 提高到 0.499，外部语义单项从 0.436 提高到 0.457；但与静态规则融合后未超过 v0.7，未作为默认部署模型。
- 交叉编码器 RankNet 调优将开发 MAP 从 0.432 提高到 0.476，外部 MAP 却从 0.428 降至 0.320，确认弱监督标签会导致跨 SDK 域过拟合。该结果保留为失败消融。
- 最终冻结全部 MiniLM 参数，只训练秩 16 的查询残差适配器。适配器为 12,288 参数、约 52 KiB，开发 MAP 相对提高 11.2%，Recall@5 相对提高 17.1%，训练本身约 4.5 秒。

### 融合、运行与当前指标

- Resolver 新增 `operation-semantic`。均衡模式融合静态、基础语义和适配语义，权重为 0.30/0.20/0.50；精度模式可先建立静态 Top-10 候选池。
- 50 个板卡操作组上，均衡模式 P@1/MAP/nDCG@10 为 0.620/0.635/0.663；Top-10 模式 P@1 为 0.640。均衡模式相对 v0.7 的 MAP 增量为 0.0063，95% 区间跨越 0，不作统计显著声明。
- 本轮已反复查看板卡聚合指标，当前权重属于探索性配置。正式论文必须以新增开发真值固定参数，并对未查看 SDK 执行一次性确认测试。
- K210 完整语义流水线已运行：19/19 操作进入绑定计划，首次链接错误由诊断器补入 `lib/bsp/syscalls.c`，第二轮生成 ELF/BIN；端到端宏平均 Precision/Recall/F1/MRR 为 0.80/0.67/0.716/0.90，语义解析耗时 47.95 秒。
- 单元测试由 33 项增加到 34 项，新增语义融合和候选重排契约测试；基础解析模式不强制依赖 torch。

详细设计、全部模型对比、公式、输入输出、文件职责和复现命令见 `docs/ir-semantic-reranking-v0.8.md`。
