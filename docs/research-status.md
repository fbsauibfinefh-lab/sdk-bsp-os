# 研究原型状态

## v0.2 已实现

- C/C++/汇编、构建规则、链接脚本和启动资产的确定性摄取；
- 版本化、可按证据追溯的 SDK Migration IR；
- 多证据加权的语义候选排序和操作角色去重；
- 带来源说明的源码/构建/链接/启动闭包；
- RT-Thread K210 工程物化和输入 SDK 替换；
- 时钟、中断、UART、GPIO、定时器功能性绑定生成；
- 绑定到 SDK 符号、签名和源码位置的证据清单；
- SCons 编译、ELF/BIN 固件收集和架构检查；
- 编译/链接错误分类及 SDK IR 反向定位；
- 缺失头文件、未定义符号的自动闭包修复和有界重试；
- 单元测试、GitHub CI 和可复现 K210 配置。

## 后续实验工作

- 增加第二个 RTOS 后端；
- 增加更多芯片 SDK；
- 在 K210 开发板上执行启动和外设回归；
- 使用 Clang/tree-sitter 提升复杂宏与条件编译下的解析精度；
- 构建人工语义/闭包真值集，执行对照和消融实验；
- 扩展自动修复类型，并评估错误修复风险与收敛性。

自动诊断迭代和功能绑定已经进入方法主链，不再作为“以后再做”的外围功能。当前仍需通过故障样本、更多 SDK 和硬件实验验证其准确率、收益和泛化能力。

当前功能绑定的层级是“可调用 SDK 适配层”：包装函数具有真实 SDK 调用、统一类型/返回值，并进入最终固件。下一阶段需要继续根据 RT-Thread 设备模型生成 `rt_uart_ops`、`rt_pin_ops`、`rt_hwtimer_ops` 等对象和注册代码；这仍是功能绑定生成的组成部分，不应与增加第二 RTOS 或扩大芯片样本混为一谈。
