# 相近任务指标与论文实验目标参考

## 1. 先给结论

相近领域没有由会议或期刊规定的统一 P@1、Recall@5、MAP 或 nDCG 录用线。论文层次主要取决于问题重要性、方法新颖性、基线强度、数据隔离、统计显著性、错误分析和端到端证据，而不是单个指标是否超过 0.80。APIBench 的系统研究也明确指出，API 推荐长期缺少统一任务定义和标准化评测，不同论文的绝对数字往往不可直接横向比较。

对本项目应区分两套目标：

- **论文方法目标**：在厂商独立 OOF 上显著超过强基线，并以冻结确认 SDK 复现。当前 v0.3 的 `0.651/0.748/0.681/0.743` 已落在近期较难代码检索结果的合理区间，但还需要确认集和端到端实验支撑 B 类投稿。
- **无人值守工程目标**：Top1 会直接进入绑定和固件，因此要求明显高于一般检索。建议继续保留 `P@1 >= 0.80、Recall@5 >= 0.90、MAP/nDCG@10 >= 0.80` 作为工程目标；若完全不人工复核，关键绑定的 Top1 精度还应接近 0.90 至 0.95，并由编译、仿真和上板回归共同保护。

## 3. 本论文适合采用的分层判据

### 3.1 达到可投稿实验质量

建议至少同时满足：

1. 厂商或上游项目独立拆分，不按函数随机拆分；
2. 相对强基线四项核心指标有 5%-15% 的稳定相对提升，关键指标 bootstrap 95% 区间不跨 0；
3. 在冻结、未参与真值修订和错误分析的新 SDK 上复现方向；
4. 提供模块消融、逐 SDK/逐操作结果、完整错误清单和运行成本；
5. 语义排序之外，再给出工程生成、编译/链接、仿真和实板行为结果。

v0.3 相对 v0.2 的 P@1、Recall@5、MAP 和 nDCG@10 分别提高 0.157、0.095、0.117 和 0.103，已经具备较强的相对方法证据。当前主要缺口不是必须把全部绝对值强行刷到 0.80，而是冻结确认集、双人真值仲裁、六套构建/行为结果和更多仿真重复实验。

### 3.2 达到自动绑定可靠性

语义 Top1 错误会被下游编译闭环漏检，因为错误函数只要签名可包装、依赖可闭包，工程仍可能编译成功。因此：

- `P@1 < 0.70`：适合候选推荐和论文实验，不适合无人值守写入全部绑定；
- `P@1 0.80-0.90` 且 `Recall@5 >= 0.90`：可将 Top5 作为强辅助，配合编译、仿真和低分人工复核；
- `P@1 >= 0.90`：才接近大规模自动绑定所需水平，但仍不能替代上板行为验证；
- 关键时钟、中断初始化等高风险操作应单独报告，不能由 UART/GPIO 的高分平均掩盖。

这些是结合相近文献和本项目错误成本给出的工程建议，不是任何 CCF 会议的官方阈值。

## 4. 论文写作建议

论文中不应写“达到 0.80 因而达到 CCF B 水平”。更稳妥的表述是：

> 在按厂商独立划分的 281 个函数级操作查询上，所提方法相对冻结预训练代码效果基线取得 0.157/0.095/0.117/0.103 的绝对提升，并通过查询级配对 bootstrap 验证；其 P@1 和 MRR/MAP 处于近期代码检索与 API 推荐研究所报告的常见区间。由于 BSP API 定位具有项目私有、跨抽象层和分级多正例特征，本文不直接比较不同候选池上的绝对数值，而进一步使用冻结 SDK、编译闭环、仿真和实板回归验证外部有效性。
